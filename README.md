# 📬 Сервис управления и мониторинга рассылок

Современный веб-сервис на Django для создания, настройки и автоматизации email-рассылок клиентам. Проект поддерживает разделение ролей (Пользователи / Менеджеры), ручной запуск рассылок, сбор логов доставки писем, а также высокопроизводительное кеширование данных.

## 🚀 Основной функционал

### 1. Управление рассылками (CRUD)
*   **Клиенты (Получатели):** Добавление, просмотр, редактирование и удаление карточек клиентов (Email, ФИО, комментарий).
*   **Сообщения:** Создание шаблонов писем (Тема, тело письма).
*   **Рассылки:** Настройка времени запуска (`start_time`), окончания (`end_time`) и выбор получателей. Статус рассылки ('Создана', 'Запущена', 'Завершена') пересчитывается динамически.

### 2. Авторизация и разграничение прав
*   **Регистрация:** Регистрация с обязательным подтверждением аккаунта по ссылке из Email (выводится в консоль разработчика).
*   **Сброс пароля:** Полноценный цикл восстановления доступа через почту.
*   **Роли доступа:**
    *   **Пользователь:** Может управлять (создавать/изменять/удалять) только своими клиентами и рассылками. Видит статистику только по своим отправкам.
    *   **Менеджер:** Имеет доступ к просмотру всех рассылок и клиентов в системе. Может принудительно **отключить** любую активную рассылку. Не имеет прав на редактирование и удаление чужих данных.

### 3. Отчетность и производительность
*   **Логирование:** Для каждой попытки отправки писем сохраняется точное время, статус ('Успешно' / 'Не успешно') и ответ почтового сервера.
*   **Дашборд:** Главная страница отображает метрики эффективности (Всего рассылок, уникальные клиенты, успешные и неудачные отправки).
*   **Кеширование:** Для снижения нагрузки на базу данных и моментальной отдачи статистики используется оптимизированный бэкенд кеширования данных в память (`LocMemCache`).

## 🛠️ Инструкция по установке и запуску

### 1. Клонирование и подготовка окружения
Откройте терминал в папке с проектом и убедитесь, что ваше виртуальное окружение (venv) активировано:
```bash
# Проверьте, что в терминале PyCharm активна ваша среда (django-mailing-service-py3.14)
```

### 2. Применение миграций базы данных
Создайте структуру таблиц в базе данных SQLite (включая кастомную модель пользователя):
```bash
python manage.py makemigrations
python manage.py migrate
```

### 3. Наполнение базы демонстрационными данными
Запустите кастомную CLI-команду для автоматического создания тестовых пользователей разных ролей, списков клиентов, писем и истории логов:
```bash
python manage.py fill_db
```

### 4. Запуск сервера разработки
Запустите встроенный веб-сервер Django:
```bash
python manage.py runserver
```
После этого откройте браузер по адресу: [http://127.0.0](http://127.0.0)

## 📁 Структура ключевых файлов проекта

```text
django-mailing-service/
│
├── config/                  # Глобальные настройки проекта
│   ├── settings.py          # Конфигурация кеша, почты и путей статики
│   └── urls.py              # Главный маршрутизатор (включает статику при DEBUG)
│
├── mailings/                # Основное приложение сервиса
│   ├── management/
│   │   └── commands/
│   │       └── fill_db.py   # Скрипт генерации тестовой БД
│   ├── mixins.py            # Разграничение прав Пользователь / Менеджер
│   ├── models.py            # Модели User, Recipient, Message, Mailing, MailingLog
│   ├── services.py          # Сервисный слой отправки писем с обработкой ошибок
│   ├── urls.py              # Карты адресов (CRUD + Auth)
│   └── views.py             # Контроллеры с кешированием плоских словарей статистики
│
├── static/                  # Статические файлы оформления
│   └── css/
│       └── bootstrap.min.css
│
└── templates/               # HTML-шаблоны страниц
    ├── base.html            # Глобальный родительский шаблон с навигацией
    ├── mailings/            # Шаблоны дашборда и списков рассылок
    └── registration/        # Шаблоны входа, регистрации и сброса пароля
```
